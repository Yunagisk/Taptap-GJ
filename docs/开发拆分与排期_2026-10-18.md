# 七宗罪：四人开发拆分与 10 月 18 日交付建议

编制日期：2026-10-11。目标日期：2026-10-18。

依据：桌面的《[必读]总策划案.pdf》（4 页）和《[可选]游戏设计文档 (1).pdf》（22 页），以及当前仓库的静态代码检查。未运行 Unity 验收；“已有基础”不表示功能已完整可用，也不包含其他协作者尚未合并的工作。

本文是建议分工与排期，不是已经确认的需求变更。以必读总案确定本期范围，详细设计用于补充一致的规则；蓝色建议、灰色初测值、红色待定项不自动视为最终需求。

## 1. 工期判断和范围

4 人如果都能稳定投入开发、已有素材可复用，在 18 日交付可从开局玩到结局的版本有机会；完整实现两份文档的全部内容风险很高。建议 13 日完成第一条贯通流程，16 日晚停止增加功能，17 日集中回归，18 日只处理阻断问题和打包。

本期完整目标按总案理解：3 类小怪、3 个原罪 Boss（懒惰优先）、独立最终首领、12 把武器、首批 3 种道具、村庄与野外事件、世界时间与罪恶、诅咒转美德、单一最新存档。

注意：正文称最终首领“独立”，因此暂按“3 原罪 + 1 最终首领”排期。总案胜利条件有一句“原罪恶魔已死”，结合前后文应明确为“最终首领死亡且玩家存活”；不要实现为杀死任一原罪就通关。

如果 14 日仍未稳定贯通，建议团队主动缩减首发内容数量，先交付 1 原罪 + 1 最终首领、4 把开局武器和 3 道具的保底版本。其余 2 个原罪与 8 把武器仍属于总案目标，延期必须作为明确的范围调整，不能称为已经完成全部总案。

B 的战斗工作风险最高：D 应承担敌人/技能资源和配置、循环数据、测试样例与 UI 素材接入，B 负责通用执行。A 也容易成为集成瓶颈，C/D 必须通过假状态和约定接口独立演示，不能等 A 完成全部系统才开始。

建议每人维护独立功能分支；场景和大型预制体同一时间只有一个编辑者，`.meta` 与资产一起提交。每天至少合并一次可运行结果，每人负责自己模块的验收，不让 A 最后一天承担全部测试。

### 11 日先约定 5 组数据/接口

以下是建议契约，不表示仓库已实现这些类：

1. **RunState**：唯一运行状态，区分 `sinValue`（罪恶进度）和 `sinCurrency`（罪骸货币）；保存装备、库存、事件、待领物品、终局状态和确定的随机结果。
2. **ActionRequest / ActionResult**：稳定 `actionId`、来源、动作类型、目标/选项、耗时与返回结果。中央结算层校验配置及当前状态，一次提交；界面只在确认成功后刷新。相同 ID 重试不能重复发奖或收费，下一次合法购买必须使用新的 ID。
3. **WorldTimeService**：逐单位推进，并返回完成、死亡或超时；只有 A 的统一入口改世界时间，休整和事件不能自行 `time += n`。
4. **BattleRequest / BattleResult**：携带遭遇 ID、玩家资源、装备、整局效果、来源节点/事件与请求 ID；返回存活资源、消耗物品和击杀记录。结算层负责一次性奖励与耗时，事件战回到原事件结果页。
5. **EffectSpec + SaveData**：B/C/D 共用治疗、状态、伤害、资源变化等效果描述；A 负责保存格式，其他人提交本模块状态。稳定 ID 对应配置，不能依赖场景对象引用保存。

在接口冻结时一起解决现有字符串武器 ID 与 `WeaponData` 资源的对应关系，避免开局选了剑、进战斗却使用 Inspector 中另一把武器。

跨日存档要覆盖“已支付移动时间，但节点内容尚未开始”等中间状态：保留 pending 请求与完成标记，读档继续原流程。若事件战尚未结算，也不能因自动保存后读档跳过战斗或重复领物品。

## 6. 各模块最低验收与高风险边界

- **购买**：余额不足、库存为 0、包满均不扣钱；一次合法购买同时扣钱、减库存、入包；重新打开商店不刷新库存；跨日重置，读档不重复补货。
- **背包装备**：村庄和营地允许配装，其他节点不能改；混合武器正确占多槽；战内不能从未装备武器列表临时换入。
- **状态**：施加当轮的持续型状态不减层；中毒→点燃→再生逐项检查死亡；疲惫禁止技能及所有决心获得；坚定满资源时不消耗；净化不能删除诅咒和美德。
- **破防**：多段中途破防只跳过一次敌人行动；当轮和下一轮保护，再下一轮开放累计；点燃在敌人行动后破防正确跳过下轮；混合单段不会按类型多算基础破防。
- **战斗**：无效操作不扣行动/资源；单体多段击杀后停止；快速连点不能提交第二个行动；技能扣费后必须执行效果；战后生命、决心、提灯和已知弱点保留。
- **世界时间**：移动 +1、普通战胜利另 +1，空节点和回村移动也耗时；购买与战外用药不耗时；所有村外耗时按规则累积罪恶。
- **休整**：三类休整恢复量、提灯和耗时不同；原地和旅馆支付到日终；途中超时后停止剩余步骤；同一营地不能重复休整，配装不消耗次数。
- **事件**：关闭未选事件不算完成；已选结果只提交一次；战斗后返回原事件；同一实例不能读档重抽；完成/过期/失效退池；满包奖励可稍后领取且不重复。
- **原罪**：出现时施加对应诅咒，击杀时解除并获得美德；不会重复出现/重复授予；普通战后清状态不清除整局效果。
- **终局**：T=87 首次开放并设置 12；后续耗时才开始扣；移动使倒计时归零时不能先进入节点；最终击杀且玩家存活时胜利优先于战后耗时超时；双方同死失败。
- **存档**：新局初始资源一致；继续恢复地图、库存、事件、装备和倒计时；同一存档读两次状态一致；保存不恢复资源；进程退出后仍可继续。
- **交付**：独立构建可从主菜单开局；无运行阻断异常；真实分辨率可操作；无缺字体、缺场景、丢引用；主菜单继续与失败后读档确实读取文件。
